# 公开市场公告核对

核对公开市场操作结果并生成跨载体一致的公告版本。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块只校验资料边界，不预先实现业务流程。

当前资料反映以下领域事实：

- 操作采用固定利率和数量招标
- 一级交易商申报后需要完成资金及抵押品交收
- 七天期限决定到期回款安排

## 本地校验

运行项目自带测试可确认样例资料能够被读取，领域标识、版本、参与方、事实和约束均保持完整。仓库不保存账号、密钥、连接串或真实身份资料。

## 公告核对服务

`src/announcement.py` 实现公告核对核心流程（仅依赖标准库）：

- **接收与去重**：`ingest_result` 录入结构化操作结果，按抓取去重键与内容哈希幂等，重复抓取不产生第二份公告；同一业务编号内容变更记为历史冲突。
- **附件提取**：`ingest_attachment` 接收经授权的表格（CSV/字典行）或图片（注入 OCR 适配器）附件，字段名归一（如"中标利率"→`fixed_rate`），数值统一为亿元/百分数 Decimal；同内容重传幂等，换内容保留修订留痕；未授权附件阻断。
- **交叉校验**：`check` 逐字段比对业务汇总与各附件来源，并对照日历（节假日、补班日、期限遇休市顺延的到期日）与发布模板（必填字段、满足方式取值），产出阻断/提示级差异与缺失清单，发布人员可在截止前查看 `deadline_remaining`。
- **人工修改**：`apply_manual_edit` 必须填理由，`approve_edit` 要求复核人不同于修改人（四眼原则），批准值消解对应差异后才可冻结。
- **冻结与发布**：`freeze` 生成内容哈希与冻结清单，`publish` 一次性渲染公众接口、网页正文、下载附件三类载体，均内嵌同一 `content_hash`；`verify_artifact_consistency` 可复核三载体一致。
- **版本与勘误**：同日多项操作合并为一份公告；零投放日照常发布并给出净投放；`initiate_correction` 对已冻结/已发布公告发起勘误，形成版本链，旧版置为已替代但保留可查。
- **溯源**：`trace_value` 从媒体引用的任一数值反查公告版本、来源（业务汇总/附件摘要）、修改人与复核人、更正链。
