# 公开市场公告核对

核对公开市场操作结果并生成跨载体一致的公告版本。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块只校验资料边界，不预先实现业务流程。

当前资料反映以下领域事实：

- 操作采用固定利率和数量招标
- 一级交易商申报后需要完成资金及抵押品交收
- 七天期限决定到期回款安排

## 本地校验

运行项目自带测试可确认样例资料能够被读取，领域标识、版本、参与方、事实和约束均保持完整。仓库不保存账号、密钥、连接串或真实身份资料。

## 公告核对服务

`src/omo/` 实现从业务结果到对外公告的核对与发布流程：

- `models.py` — 操作结果、业务汇总、公告版本、人工修改、附件与字段级溯源；数值字段统一规范化，冻结内容以内容哈希标识
- `calendar.py` — 历史交易日历：节假日、周末与补班判断，到期日按自然日计并顺延到下一交易日
- `extraction.py` — 附件字段提取：表格按 CSV 解析，图片需注入 OCR 能力，未注入时拒绝提取
- `service.py` — 核对服务主体：
  - 幂等接入：同一操作只对应一份公告，重复抓取不产生第二份有效公告；冻结后结果变更必须附更正说明
  - 交叉校验：与业务汇总逐项核对（固定利率、操作量、期限、满足方式），并对照日历与发布模板，附件提取值不一致即报错
  - 人工修改：必须填写理由，且由申请人之外的人员复核后才落版
  - 版本链：草稿 → 复核 → 冻结 → 发布；公众接口、网页正文、下载附件共用同一冻结哈希
  - 勘误：已发布公告的更正生成带理由的新版本，旧版本保留可追溯
  - 截止前报告：按交易日列出差异、缺失字段、缺失公告与未发布项
  - 数值溯源：从媒体引用的任一数值定位来源凭据、审核人与更正链
